# 마니또 뽑기

서버·DB 없이 `index.html` 파일 하나로 동작하는 마니또 뽑기 웹앱입니다.
하나의 고정 주소(GitHub Pages)를 여러 그룹이 계속 재사용하고, **방장도 다른 사람의 결과를 알 수 없습니다.** 결과는 각 참가자의 PIN으로만 암호화·복호화됩니다.

- 단일 `index.html` (HTML + CSS + JS 인라인, 빌드 도구·프레임워크 없음)
- 암호화는 브라우저 기본 Web Crypto API만 사용
- 데이터는 어디에도 저장하지 않음 — 모든 정보는 URL 해시(#)와 사람끼리 주고받는 코드에 담김
- 모바일(카톡 인앱 브라우저) 우선 반응형, 한국어 UI

---

## 사용법 (3단계)

### 1. 방장: 방 만들기
1. 첫 화면에서 **그룹 이름(필수)**, **마니또 공개일(필수, 오늘 이후)**, **선물 예산(선택)**을 입력하고 **방 만들기**를 누릅니다.
   - 예산을 비우면 예산 영역은 어디에도 표시되지 않습니다.
2. 만들어진 **방 링크**를 복사해 단톡방에 공유합니다. 링크는 `.../#r=...` 형태입니다.

### 2. 참가자: 등록 코드 보내기
1. 방 링크를 열고 **[참가 등록]** 탭에서 이름과 **PIN(숫자 6자리 이상)**을 입력합니다. PIN은 두 번 입력해 확인합니다.
   - 안내: **PIN은 결과 확인에 꼭 필요해요. 잊어버리면 다시 볼 수 없어요.**
2. 화면에 표시된 **등록 코드**(`MANITO1-...`)를 복사해 방장에게 개인톡으로 보냅니다.

### 3. 방장: 매칭하고 개인 링크 배포
1. 같은 방 링크의 **[방장 모드]** 탭에서 받은 등록 코드를 모두 붙여넣습니다. (여러 개 한 번에, 줄바꿈 구분)
2. **등록 코드 확인**을 누르면 등록 인원 목록(이름만)이 보입니다.
   - 다른 방의 코드·깨진 코드는 어떤 코드가 왜 제외됐는지 표시됩니다.
   - 같은 이름이 두 번 있으면 매칭이 차단됩니다. 최소 3명이 필요합니다.
3. **매칭하기**를 누릅니다. 매칭 결과는 화면에 절대 표시되지 않고, 이름별 **개인 링크 복사** 버튼만 나타납니다.
   - 예: "지민님에게 보낼 링크 복사"
4. 각 참가자에게 개인 링크(`.../#m=...`)를 개인톡으로 보냅니다.

### 4. 참가자: 결과 확인
1. 개인 링크를 열면 "OO님의 마니또 확인" 화면이 뜹니다. 그룹 이름·공개일·D-day(예산을 입력한 방만 예산 포함)가 항상 표시됩니다.
2. PIN을 입력하면 카드가 뒤집히며 마니또 이름이 공개됩니다.
3. PIN이 틀리면 "PIN이 맞지 않아요" 안내가 나옵니다. (시도 횟수 제한 없음)

### D-day 표시
- 공개일 옆에 `D-12`, `D-3`(남음), `D-DAY`(당일), `D+2`(지남)로 표시됩니다. 숫자 앞에 0이 붙지 않습니다.
- 보는 사람 기기의 현지 날짜 기준으로 계산합니다.
- 지났으면 "마니또 공개일이 지났어요" 안내가 함께 표시됩니다.

## 어떻게 방장이 결과를 볼 수 없나요?

1. **등록 시(참가자 브라우저)** — ECDH P-256 키 쌍을 만들고, PIN에서 PBKDF2(SHA-256, 랜덤 salt, 600,000회)로 만든 AES-GCM 키로 **개인키를 암호화**합니다. 등록 코드 = `{ 버전, 방 ID, 이름, 공개키, 암호화된 개인키, salt, iv }`
2. **매칭 시(방장 브라우저)** — 참가자마다 **일회용 ECDH 키 쌍**을 만들어 참가자 공개키와 공유키를 도출(HKDF → AES-GCM)하고, 마니또 이름만 암호화합니다. 일회용 개인키와 평문 결과는 메모리에서 버려집니다.
3. **확인 시(참가자 브라우저)** — PIN → PBKDF2 → 개인키 복호화 → ECDH → 마니또 이름 복호화.

방장은 PIN을 모르기 때문에 개인 링크를 열어도 결과를 볼 수 없고, 서버도 없어서 어디에도 기록이 남지 않습니다. 모든 페이로드는 JSON → UTF-8 → base64url로 인코딩되며 버전 필드(`v:1`)를 포함합니다.

> 주의: PIN을 잊으면 복구 방법이 없습니다. 이것은 설계상 특징입니다(아무도 복구할 수 없어야 안전합니다).

## 로컬에서 실행·테스트

파일을 브라우저에서 열어도 되지만, Web Crypto는 보안 컨텍스트(https 또는 localhost)에서만 동작합니다. 로컬 확인은 간단한 서버를 권장합니다:

```bash
# 예: Python 내장 서버 (localhost는 보안 컨텍스트로 인정됨)
python3 -m http.server 8000
# → http://localhost:8000 열기
```

핵심 로직 테스트(브라우저 없이, Node 18+):

```bash
node tests/run-tests.mjs
```

index.html의 `<script>`를 그대로 불러와 다음을 검증합니다.

- 3명·5명·10명 매칭 1,000회씩(총 3,000회) — 자기 배정·중복 배정 0건
- 4명 등록 → 매칭 → PIN 확인 전 과정 시뮬레이션
- 틀린 PIN 복호화 차단
- 다른 방 코드 필터링 (거절 사유 구분)
- 예산 입력/미입력 방의 페이로드 필드 유무
- D-day: 오늘(D-DAY) / 내일(D-1) / 어제(D+1) / 선행 0 없음
- 한글·공백·이모지 이름 전 과정 처리

## 파일 구성

```
index.html            # 웹앱 전체 (화면 UI + 코어 로직)
tests/run-tests.mjs   # Node 18+ 테스트 (index.html의 <script>를 직접 로드)
README.md             # 이 문서
```

`index.html` 안에서 핵심 로직은 함수로 분리되어 있고 `ManitoCore` 객체로 노출됩니다(매칭: `assignManitos`·`createPersonalLinks`, 인코딩: `encodePayload`·`decodePayload`, 암호화: `createRegistrationCode`·`openPersonalLink`, D-day: `calcDday`). UI 코드는 `document`가 있을 때만 실행되므로 Node 테스트에서도 같은 스크립트를 안전하게 재사용합니다.

## 배포 (GitHub Pages)

1. GitHub에 **Public** 저장소를 만들고 이 폴더 내용을 push합니다.
2. 저장소 **Settings → Pages**에서 Source를 `main` 브랜치 / `(root)`로 설정합니다.
3. `https://<사용자명>.github.io/<저장소명>/` 주소로 접속해 등록부터 확인까지 테스트합니다.

배포 후에는 주소가 고정되므로, 여러 그룹이 같은 주소를 계속 재사용할 수 있습니다.

## 예외 상황 안내

- 깨진 링크나 코드 → "링크가 올바르지 않아요" 안내 + 첫 화면 버튼
- 공개일 미입력 → 방 만들기 차단 + "공개일을 선택해 주세요" 안내
- 다른 방의 등록 코드 → 어떤 코드가 왜 제외됐는지 표시
- 같은 이름 두 번 등록 → 매칭 차단 + 경고
- Web Crypto를 쓸 수 없는 환경(HTTP 등) → 상단에 안내 문구 표시
